1 Semantic Chunking

Instead of blindly splitting every 900 characters (P1), P2 splits at natural topic boundaries detected by measuring the semantic similarity between consecutive sentences.

Algorithm: 4 Steps

# Step 1: Split into sentences
sentences = re.split(r'(?<=[.!?])\s+(?=[A-Z])', text)

# Step 2: Embed each sentence
embeddings = model.encode(sentences, normalize_embeddings=True)

# Step 3: Find breakpoints (similarity drops)
for i in range(len(embeddings) - 1):
    sim = np.dot(embeddings[i], embeddings[i + 1])
    if sim < (1 - breakpoint_threshold):   # default threshold: 0.3
        breakpoints.append(i + 1)          # new chunk starts here

# Step 4: Group sentences between breakpoints into chunks
# Merge small chunks (< min_chunk_size) with neighbors
# Split large chunks (> chunk_size) with overlap

P2 also offers a recursive chunker that tries to split on natural boundaries in priority order:

separators = [

    "! ",     # 4. Exclamations
    "? ",     # 5. Questions
    "; ",     # 6. Semicolons
    ", ",     # 7. Commas
    " ",      # 8. Words

2 Vector Search (Dense Retrieval)

Same as P1 — embed the query, find the nearest vectors in ChromaDB. But in P2 it fetches 3x more candidates (k * 3) because the hybrid + reranking pipeline will filter them down.

How Vector Search Ranks

ChromaDB returns a raw distance (lower = more similar). P2 converts this to a similarity score:

# Convert distance to similarity (0 to 1)
vector_score = 1 / (1 + distance)

# distance=0.0 → score=1.0  (identical)
# distance=0.5 → score=0.67
# distance=1.0 → score=0.50
# distance=5.0 → score=0.17  (very different)

Why Vector Search Alone Isn't Enough

Vector search captures meaning but can miss exact keyword matches:

QueryVector Search FindsVector Search Misses
"BM25 algorithm"Chunks about search algorithms, rankingChunk that literally says "BM25" but is phrased differently
"error code 404"Chunks about HTTP errors, web issuesChunk containing the exact string "404"
"Dr. Smith's paper"Chunks about research, papersChunk that mentions "Dr. Smith" by name

This is why P2 adds BM25 keyword search as a complement.

3 BM25 Keyword Search (Sparse Retrieval)

BM25 (Best Matching 25) is a keyword-based ranking function. It scores documents by how often the query terms appear, adjusted for document length and term rarity.

Tokenization Pipeline

def _tokenize(self, text):
    text = text.lower()                          # normalize case
    tokens = re.findall(r"\b\w+\b", text)        # split on word boundaries
    tokens = [t for t in tokens                   # filter:
              if len(t) > 1                       #   remove single chars
              and t not in self._stopwords]       #   remove "the", "is", etc.

    def stem(tok):                                # light stemming:
        for suf in ("ing","edly","ed","ly","es","s"):
            if tok.endswith(suf) and len(tok) > len(suf) + 2:
                return tok[:-len(suf)]            #   "running" → "runn"
        return tok
    return [stem(t) for t in tokens]

Example: "What is machine learning?" becomes ["machin", "learn"]

BM25 Scoring Formula

For each query term, BM25 computes a score based on three factors:

score(q, d) = IDF(q) * tf(q,d) * (k1 + 1) / (tf(q,d) + k1 * (1 - b + b * |d|/avgdl))
IDF
Inverse Document Frequency — rare terms score higher ("machine" > "the")
TF
Term Frequency — more occurrences = higher score (with saturation via k1=1.5)
|d|/avgdl
Length normalization — shorter docs with same term count score higher (b=0.75)

4 Score Fusion

P2 combines vector and BM25 results using weighted linear combination, then deduplicates by chunk ID.

The Formula

# Default weights
vector_weight = 0.7    # semantic understanding
bm25_weight   = 0.3    # keyword matching

# For each chunk found by either method:
combined_score = vector_weight * vector_score + bm25_weight * bm25_score

# Chunks found only by vector: bm25_score = 0
# Chunks found only by BM25:   vector_score = 0
# Chunks found by both: get full combined score (boosted!)

5 Cross-Encoder Reranking

The final stage feeds each (query, chunk) pair through a Cross-Encoder that evaluates relevance jointly — much more accurate than independent embeddings.

Bi-Encoder vs Cross-Encoder

Bi-Encoder (Stage 1-2)

Query  ──► Encoder ──► Vector A
                                    ► cosine(A, B)
Chunk  ──► Encoder ──► Vector B

Fast: encode once, compare many
But: independent encoding misses
     query-document interactions

Cross-Encoder (Stage 5)

[Query] + [SEP] + [Chunk]
         │
    ┌────▼────┐
    │Transformer│   Sees BOTH together
    │ 6 layers  │   Full attention between
    └────┬────┘   query and chunk tokens
         │
    Relevance Score (single number)

The Code

class Reranker:
    def rerank(self, query, results, top_n=4):
        # Create (query, chunk) pairs
        pairs = [(query, r["text"]) for r in results]

        # Cross-encoder scores all pairs jointly
        scores = self.model.predict(pairs)

        # Attach scores and sort
        for result, score in zip(results, scores):
            result["rerank_score"] = float(score)
        results.sort(key=lambda x: x["rerank_score"], reverse=True)

        return results[:top_n]  # Return only the best
